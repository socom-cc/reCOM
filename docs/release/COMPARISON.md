## Classes

- **exact**: equal masked instructions and layout (address operands masked: `j`/`jal`
  targets, address-range `lui` immediates, `$gp` offsets, low halves paired with an
  address `lui` through the function's control flow), and every call and data
  operand consistent with the other pairs;
- **deviating**: the same function with differences;
- **unsure**: a candidate pair the evidence does not settle (see the unsure section);
- **new**: release function with no prototype counterpart;
- **removed**: prototype function with no release counterpart.

Similarity is `difflib.SequenceMatcher.ratio()` over the masked instruction words,
2M/(n+m) with M instructions matched in order: the share of instructions equal.
Shape similarity is the same over instructions with every immediate removed; flag
`imm-only` marks equal-size pairs whose shapes are identical, so only immediates or
offsets differ (such a pair is deviating whatever its similarity). Operation similarity
is the same over the operations alone (no registers, immediates or targets): it
survives register-allocation changes.

A function's references are its calls, tail calls and loaded code addresses (function
pointers), in instruction order. An exact pair maps them position for position; any other
pair aligns the two ordered lists on the targets already paired (targets that occur once
in both lists first, so a repeated SDK call cannot pull its neighbours to the wrong
occurrence), and between two such anchors maps the unpaired targets that resemble each
other (similarity >= 0.20 or operation similarity >= 0.50), in order; when exactly one
unpaired target is left on each side between the same two anchors, that 1-to-1 slot pairs
them (evidence `slot-only`). A callee is paired when the callers' votes for
it have a strict majority, exact callers first. Strings and `(file, line)` tokens of the
debug allocators count as identity evidence only when exactly one function on each side
uses them; source-file names alone never do.

Flags: `callee-changed` (a reference leads to a function paired elsewhere: the callee was
replaced), `call-and-slot` (referenced at the prototype function's place by a paired
caller and in its slot between the order anchors), `role-only` (an exact caller references
it at the same place but the body was rewritten: the prototype name may not carry over),
`owner-moved` (a template instance the release emits among another file's functions;
the owner is that file and the prototype owner is kept in the JSON copy), `moved` (out of
order), `ambiguous`, `low-similarity`, `owner-guess`, `copy`.

`call`: non-exact pairs made by call-tree propagation (the pairing does not look at
similarity, so this is the distribution of real counterparts); `position`: pairs from the
positional alignment (which needs 0.30 to propose a pair); `string`: pairs from unique
shared strings; `global`: mutual best matches anywhere among the functions left over
(moved code, similarity >= 0.30); `null`: a prototype function of a call/position pair against the release
functions two places before and after its partner, of comparable size (unrelated pairs).
Small functions look alike (accessors, stubs), so the null of all sizes has a tail near
1.0; for them the order between anchors decides and a pair is unsure (`ambiguous`) when an
unpaired alternative in the same gap scores within 0.05.

Thresholds, from the >= 16-instruction rows: 83.4% of null pairs stay below 0.50 and
74.1% below 0.30, while 82.3% of call-tree counterparts reach 0.50. So:

- a positional, `global` or `call-deviating` pair is deviating at similarity >= 0.50, unsure
  from 0.30 to 0.50, unless it is referenced at its place by a paired caller and in its
  slot with operation similarity >= 0.40 (`call-and-slot`);
- a pair with independent evidence (called at the same call site of an exact pair, a
  unique shared string, the entry point) is deviating at similarity >= 0.30 or operation
  similarity >= 0.70; a pair an exact caller references at the same place and in its slot
  is deviating whatever its similarity (`role-only`); otherwise unsure (`low-similarity`);
- `slot-only` (deviating, weak by its evidence): the only unpaired function on each side
  between two consecutive order anchors, or between the same two anchors of a paired caller's
  references; no similarity or n-gram prefilter, but the size ratio must be >= 0.10, an address
  slot needs operation similarity >= 0.25, a reference slot must also lie in the function's
  own address slot, and paired callers on both sides must lie within 64 KB of each other in the
  prototype; a positional pair alone between its anchors that misses the thresholds becomes
  `slot-only` too;
- below 256 bytes, an operation similarity >= 0.60 stands in for the 3-gram prefilter;
- a global look-alike under 256 bytes outside its slot needs callers that agree (a paired
  caller on one side whose partner calls the other) unless neither side has paired callers;
- an exact byte match whose calls lead to functions paired elsewhere is deviating
  (`callee-changed`) when it is in order, unsure when moved; one whose data operands point
  to another kind of region (`ref-kind`) is unsure.

A pair settled by a checker goes into `docs/release/settled-pairs.tsv` (release address or
`removed`, prototype address or `new`, basis, checker, date); an address that is not a
function start of its image stops the run.

The tool reads `support/socom.elf` and `support/SCUS_971.34` (refused unless their
SHA-256 values are the pinned ones), the optional `build/cache/source-graph.sqlite`
for prototype classification, and the `src/` annotations for owners. Same inputs, same bytes.
