# Audit of list large-ui-b (2026-11-16, socom-port-audit-ui-b)

The 20 large functions of the rest of zUI: `gamez/zUI/zui_cleanup.cpp` (2), `zui_skb.cpp` (9),
`zui_spec.cpp` (9); 37,160 bytes. Started on HEAD aaf00559; HEAD moved to 03604c19 meanwhile
without touching zUI or the headers these files use. Judged in the scan's rank order, each over
its whole address range, on the ELF offsets the zui.h / zui_skb.cpp layout comments give (the
port's own layouts differ: the scan's offset lists are mostly that). Every float constant of the
judged bodies was checked against its ELF word; none is inexact.

Defect rate 2 / 20 = 10%; A or B 1 / 20 = 5%. The C row is only the form of a float test (NaN).

## Fixes (ELF evidence)

- B, #11 CreateSoftKeyboard 0x3a7940 (in the helper ReadSkbStringProps): a UserStringProps /
  PurposeStringProps COLOR's element 2 goes to the string colour's y and element 1 to its z
  (0x3a8548..0x3a8594, 0x3a88bc..0x3a8908); the port stored them in order. Written as the ELF has
  it, with a quirk comment. Masked: every retail COLOR is 255 255 255 (UiParams.rdr).
- C, #3 CSoftKeyboard::Tick 0x3a2c90: the repeat count's "repeating" test was held > 0; the ELF
  tests !(held <= 0) (c.le.s / bc1f, 0x3a2d84, 0x3a2e78).

## Kept deviations

- #15 CUIListBoxSpec ctor, #13 CRadioStripSpec ctor, #12 CUIMapCtrlSpec ctor: members and stack
  slots the ELF leaves as they were when a key is absent are zeroed (reasons already in the code).
- Not new, confirmed: the keyboard's Text() gives "" for a NULL text where the ELF strlen's
  GetString() unchecked (HandleInput, HandleUsbKbd, AddCasedChar: reached only before any text
  is set; mod-zui.md part 3).

## Leads for other lists

- `CTextSpec::CTextSpec(_zrdr*)` 0x399fe0 and `CImageSpec::CImageSpec(_zrdr*)` 0x39a840 (medium
  band) were compared through their inline copies in GetObjectSpec / the list box ctor: same.
- `CSoftKeyboard::ShutdownBegin` 0x3a3470 and `SetInsertPt` 0x3a3ac0 (small / medium): their inline
  copies in HandleInput, HandleUsbKbd, OnAltKey and AddCasedChar match the port's single bodies.
- The skb ptmf words (0x43b8a8.. 12 bytes each: delta 0, vtable offset, vptr +0xc) decode against
  `__vt__9C2DButton` 0x473860: 0x3c SetActive, 0x40 SetNormal, 0x60 SetPressed.

## What the packets lacked

- Same-file helpers the bodies call: LoadButtonState (#16), the keyboard's inline helpers
  MoveHighlight / SetInsertPt / BackSpace / Accept / ShutdownBegin / ReadSkbStringProps /
  ReadSkbRect / RdrElementInt (#3 to #11); read from the source.
- #3 Tick: the scan mapped an 8-byte port function (not this body); the body was read from the
  source.
- The ptmf constants (shown as "@2364" with no words), the DoIt jump table 0x463230 and the Clear
  key's string 0x4631c0 (""), the MSL `init<const ActionItem*>` body 0x39ae40 the copies call,
  the C2DButton vtable, the C2DString colour offset (+0x50) and the CValve value width (16 bits):
  fetched with sym.py / dx.ps1.

## Runs

- No targeted trace: the B fix is masked on this disc (every COLOR 255 255 255) and the keyboard
  shows only on online screens; ZuiInit / CreateSoftKeyboard run at every boot.
- `gate.ps1 -Only default,frontend -Build audit-ui-b-gate` on HEAD 03604c19 + mine.txt: PASS
  default (main menu at 15.4 s), PASS frontend (options screens, 13 menu switches); no STOP. The
  default build links. Nothing a menu allocates or frees changed, so no round trip.
