# Audit of list medium-ui-b (2026-11-19, socom-port-audit-mui-b)

The 70 medium functions of the rest of zUI (26,404 bytes): `gamez/zUI/zui.cpp` (12),

GCC's vtable pointer and the spec classes' member order).

## Fixes

- B `CGameMenu::RunEventAnim` 0x382030: the ELF returns whether an anim ran (`move v0,s6` at
  0x382150) and `CMenuState::RunEventAnim` returns that (0x378ca8); the port's was void and
  CMenuState returned 1 for any known event. Now bool in zui.cpp; the zgame.h declaration and
  st_menu.cpp (its deviation comment removed) are edit files. Only the online
  UILobbyEventHandler reads the result.

## Kept deviations (reasons in the code)

- `CGameMenu::MakeButtonActive` 0x3817e0: a found node without a 2D visual makes the ELF call
  SetActive and the sound through a register left from its caller (0x381938); the port skips them
  (comment rewritten to say so; as `CGameMenu::Tick`'s in large-ui-a).
- `CUIVarManager::Add` 0x39da20: no free slot returns NULL (the ELF uses +0x18 of NULL).
- `CUIVarManager::UnSerialize` 0x39d730: a save without a value is not cloned from NULL.
- `CCheckBoxSpec`, `CCycleButtonSpec`, `CHandlerButtonSpec` ctors (0x395f50, 0x3952e0, 0x397970):
  values the ELF leaves as new or the stack left them when a key is absent start 0.
- Noted, not graded: inline display-object ctors that also zero members LoadSpec always sets
  (list box, check box, slider bar, `CGameDlgDesign`'s font-lib flag).

## Leads for other lists

- `UIVarMixin::DetachUIVar` returns whether it detached (0x39e100); the port's is void (zui.h
  says so). Its zUI callers rebuild the result; a caller elsewhere that uses it would need it.
- The port's `_zvid_public` puts `pcrtcDo` at +0x55 where the ELF has +0x59 (zvid.h, the s64
  frame number's alignment); self-consistent, only a layout note.

## What the packets lacked

- The ptmf words the keyboard passes to `__ptmf_scall` (0x43b8e8 SetNormal, 0x43b8f8 SetActive:
  shown as "@2493" / "@2499" with no words; `sym.py`).
- Instructions the compacted listing drops: PrepModels' target 0x38159c (a nop) and DetachAll's
  0x39eaac had no line; `dis.sh` used.
- The tail of `CMenuState::RunEventAnim` 0x3788c0 (the caller that reads row 5's result) and the
  callers' use of a return value in general; `VALVE_TYPE` values (`VTYPE_TEMP` 2, `VTYPE_PERM`
  1) and `ZRDR_TYPE` values; the `_zrdr` bitfield layout behind the word copies.
- Nothing else: helper bodies, vtable slots and enum values the bodies name were there.

## Runs

- Default build (`default.sh audit-mui-b-def`, HEAD bc92db2f + zui.cpp + the two edit files via
  shared.txt): library and link exit 0.
- Smoke boot of that build (`run.ps1 -Build audit-mui-b-def -Name muib-smoke -Seconds 60`): the
  intro movies, `dlgMenu.rdr` (main menu, its five ONSTART event anims run) at 24.2 s and the
  attract `dlgHype.rdr` at 34.8 s; no STOP or exception. No targeted trace: the B fix is online
  only.
