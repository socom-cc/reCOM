# Audit of the large HUD functions, list hud-a (2026-11-16, socom-port-audit-hud-a)

List `large-hud-a` of the correctness audit ([AUDIT_PLAN.md](../AUDIT_PLAN.md)): the 43 fenced
functions of 700 bytes or more (60,976 bytes) in `hud_actionbitmap.cpp`, `hud_ingame_weaponsel.cpp`,
`hud_lensflare.cpp`, `hud_linemap.cpp`, `hud_mapcompass.cpp`, `hud_missioncams.cpp`,
`hud_teammatenames.cpp`, `hud_teamnames.cpp` and `hud_weaponsel.cpp`. Judged in the scan's rank
order (`build/port/audit/scan-large-hud-a.md`) from the per-function packets, each body compared
with the ELF instruction by instruction (operand order, widths and signedness, float operation
order, constant words, call arguments, stores, guards), including the port helpers that stand for
the ELF's inline code. HEAD d17cfec1 (cb01af90 at the build); no marker moved, no function moved
file.

2026-11-20 (audit-closeout): kept guards removed, now DEFECT-FIXED C: #16, #19 (the user's rule: the prototype's behaviour is kept; see [audit-closeout.md](audit-closeout.md)).
bodies were written with the ELF's float order already (`c + (a + b)` sums, `2 (475 dT)` steps,
the inlined Increment compares) and the float-constant pass had fixed their literals.

## Fixes (ELF addresses)

- Row 25, `MapCompass::Tick` 0x3cb160 (hud_mapcompass.cpp), C: the inside-ring offset was
  `(sine x 65) x near`; the ELF forms `65 x near` once and multiplies sine and cosine by it (block
  0x3cb840). Regrouped. Also the length now comes from `CPnt3D::Normalize`'s return value as in the
  ELF (bit-identical: the separate `sqrtf` summed the same terms with a zero y; its comment said
  Normalize was void, which it no longer is).
- Comment only, row 17, `CLensFlareSaturate::LoadRdr` 0x3bdcc0: the early return on a missing
  `lensflare.rdr` was labelled a port deviation; it equals the ELF, whose lens_flare search in the
  NULL reader gets NULL from `zrdr_findtag` (0x23dca0) and frees nothing.

## Kept deviations (reasons in the code)

- Row 19, `CZLineMap::TickWayPoints` 0x3c7a70: the ABLE / BRAVO labels skip a NULL string where
  the ELF writes through it (only with all 32 labels used).
- Row 16, `CLensFlareSaturate::Tick` 0x3bd640: the NULL test before the light node's opacity store
  (an `active` lensflare.rdr without a light_source leaves it NULL; m8 has no lensflare.rdr).

ELF quirks kept and noted: `CActionTxtrMachine::Open` / `SpecializeActionString` read the global
`ActionTxtrMachine_HUD`'s list, timer bitmaps and pickup node instead of `this` (the only object
they run on); `CWeaponSel::OnScrollUp` / `OnScrollDown` reload slot 1's highlight with texture 0;
`CWeaponSel::OnOpen` reads the selected item before the owner test; `CInGameWeaponSel::
PlaceWeaponText` returns at a loadout id with no weapon; `CZLineMap::TickAnchors` would take an
unset stack colour for an out-of-range type (unreachable).

## Leads for other lists

- `src/gamez/zTwoD/ztwod.h:202`: `C2DBitmap` declares a stray `bool GetTrans() const` beside the
  defined `float GetTrans()` (0x3037d0 returns the alpha float); non-const callers get the float
  one, a const call would pick the undefined bool overload. Remove with the zTwoD list.
- `CActionTxtrMachine` layout: the scan puts the port's `m_driver` at +0x3cc against the ELF's
  +0x3f0 (accessed by name, so harmless; for the layout checks).
- `hud_lensflare.cpp` `lf_tagstring` (a port helper, no fence) tests for a NULL value where the
  ELF reads byte 0 of the NULL a tag without a value gives; never reached with well-formed data.

## What the packets lacked

Judged 43 of 43. The packets were enough for the instruction comparison of every row; 16 rows
needed a fetch, all of the same two kinds:

- port helpers the bodies call instead of the ELF's inline code (not in the packets):
  `FindLineData`, `IsObjectiveLine`, `NextMapString`, `LoadMapString` (hud_linemap.cpp),
  `CAiMap::GetCellCenter` (zai.h), `IgwsLoadHighlight`, `IgwsPlaceSlot`, the two `Increment`s and
  `PlaceSlot`, `lf_tagstring`;
- callee facts: vtable slots (`CHudBrightText` +0x68, `CWorld` +0x24 / +0x48),
  `zrdr_findtag`'s NULL handling, the body of `CPnt3D::Normalize`, enumerator values (EQUIP_ITEM,
  PadBtnFunc, PAD_BUTTON, MENU_STATE, ZOOMSTATE), string literals at ELF addresses, and the
  `C2DBitmap::GetTrans` declarations.

A packet section with the bodies of same-file static helpers the function calls, and the
enumerator values of compared constants, would have removed most fetches.
