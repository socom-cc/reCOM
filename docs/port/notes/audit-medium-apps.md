## Fixes

- C `OrdersMenu::~OrdersMenu` 0x177f60: the port's extra `cmd_table = NULL` removed; the ELF
  leaves the pointer to the freed table (0x177fbc) and the ctor news a new one unconditionally.
- C `OrdersMenu::EnableTuples` 0x17aed0: a differing word id is remembered even when negative (the
  move is in the `bltz` delay slot, 0x17af4c / 0x17af6c / 0x17af8c), so a run broken by -1
  enables its word again; recoEnableWord returns without recognition, which never starts.
- C `TickMpStats` 0x3dd3c0: no NULL test of the candidate or the MVP (0x3dd45c, 0x3dd4bc).
- C `SetStatLbUiVar` 0x3dd5a0 and `SetFinalTeamTotalsUiVar` 0x3dded0: no seal test before the
  team read (0x3dd654, 0x3ddf60); the same ELF quirk the large list kept in `CMPExitState::Init`
  and `SetMpStatUiVars`. Not reachable offline.

## Kept deviations (reasons in the code)

- `cbrecoResult` 0x335de0: the word ids are stored only below 3 (the ELF writes past the array
  for a longer phrase, 0x335ef8); the callback is never registered (see below).
- `Headset::Remove` 0x2f2b30: the current line's type is read only with a line set; the ELF
  (0x2f2c8c) reads it through a NULL m_sound, from address 0x20 (comment made explicit).
- `Headset::DeQueue` 0x2f30f0: a skipped entry advances the loop (the ELF loops for ever on it;
  no ELF caller passes a skip list).

## Notes on reachability

- The voice recogniser never starts in the ELF: recoShouldInit's only store is `sb zero` in
  recoInit (0x336d90) and recoInited's only nonzero store (0x336c44) follows the recoShouldInit
  test in recoInit2. Every reco function's part behind recoInited is dead code; the port leaves
  it out, and the gsapi callbacks are registered only from that dead set-up.

## Leads for other lists

- `CNetClock::GetTimeInGameSec` 0x3dde10 and `GetTimeInRoundSec` 0x3dde60 (st_mpexit.cpp, small
  band): the ELF converts through fptoui (0x3dde4c, 0x3dde9c); the port's `(unsigned int)` can
  differ only for a negative value, which 0.001 * (f32) of the u32 members cannot give.
- `SOCOM_PORT_HEAP_KEEP_MENU_ZAR` (CMenuState::UnInit) and `SOCOM_PORT_HEAP_SHRINK_TEXLIST`
  (CCoreState::auxUnload) are off-by-default port deviations; the default build is the ELF's.

## What the packets lacked

- #47 (CLoadState::Init): the CZNetGame member names at +0x94..+0x9a and the MP_MINOR / MP_MAJOR
  enumerator values (named in the body, not listed); fetched with `off.py` / `denum.py`.
- #43: the archive name pair `lui 0x46 / addiu -22112` (0x45a9a0 "readerx.zar") was left
  unresolved, so the scan reported the string as port-only.
- #13 / #11: the body of `orders_play` behind PlayScrollSound (one level too deep).
- #40: the TexPhase row width ([17][3]) needed to read +0x90 / +0xa0.
- #36 / #37: the `_zmalloc` acquire / release bodies and member offsets (zsys.h).
- Data writers: whether a flag is ever set (recoShouldInit) needs a grep of the reference
  disassembly; a "stores of this global" line per guard variable would settle such stubs.
