# Audit of list large-anim-c (2026-11-16, socom-port-audit-anim-c)

34 zAnim functions (48,068 bytes) in `gamez/zAnim/zanim_anim.cpp`, `zanim_cmd_tick.cpp`,
`zanim_load.cpp` and `zanim_menu.cpp`. HEAD 4719c92e. Judged in the scan's rank order, each over
its whole address range.

Method: each function was read instruction by instruction against the port's body, including
the port helpers that the ELF inlines (motion_material, motion_contact_material, OpenZAR,
LoadZAR(CZAnimZAR*), CloseZAR, AddAnimToWorld, RemoveAnimFromWorld, ReRootAnim, Running,
StopParticleSources, CreateRootNode, GetNodeRef, GetRootNode, UiApplyStickPreset, UiSetRealVar,
UiSetValve, UiVarString), with the DWARF layouts of the classes they touch.

Defect rate 3 / 34 (B 1 / 34).

Fixes:
- B, #20 zAnimObjectMotionTick: the ELF clears its ground and ray material-entry registers once
  before the contact loop and its search writes them only on a match (0x1bb854, 0x1bbc30), so a
  second contact in the same frame on a material without an entry keeps the first contact's entry
  (elasticity, sequence, sound); the port's motion_material answered NULL. It now returns the
  previous entry.
- C, #20: the sound_handle NULL test before PlaySound3D (0x1bc148; GetSoundRef already answers NULL
  for a ref without a handle) removed.
- C, #26 zAnimParticleSourceTick: the m_diNode NULL test before SetActive (0x1bfa60 calls it
  unchecked; the port's Source constructor now always makes the node) removed.
- C, #34 UISwitchMenu: the m_arg_list NULL test before GetCharP (0x1d5668 calls it unchecked, as
  the port's other INPUT_STRING sites do) removed.

Kept deviations (reasons in the code): #27 LoadZAR(const char*, const char*) calls the out-of-line
LoadZAR(CZAnimZAR*) (0x1c0340), whose Anim_Sets NULL test (0x1c043c) the ELF's inlined copy lacks
(the ELF would walk a NULL key; comment added); #34's NULL-name return where the ELF strcmps NULL
(reason completed). Already recorded and confirmed: the void returns of AnimLoadAnim,
AnimLoadNameZRDR, Unload, CloseZAR and OnWeaponHit (no caller reads the ELF's value), the port
trace blocks in #12 and #23 (empty unless a trace build).

ELF quirks kept (commented in the code): OBJECT_MOTION's reflection dropped for 0x4000 (#21) and
the stale material entries (#20); OBJECT_MOTION_FROM_TO's "changed" set without an argument and
ComputeRunTime on the stored "to" (#19); the SOUND node flag looking a node up for nothing (#23);
apply_script_frame's frame_count left counted (#17); AnimLoadNameZRDR loading only the first name
(#29); the world-velocity chain of PARTICLE_SOURCE without the reflection the local chain has
(#26); UIStoreOptions / UIInitializeOptions' inverted INVERT_PITCH and STEREO senses (#31, #32).

Float checks: the three-term sums (x*x + y*y) + z*z (adda / madd) in #21, #20, #19, #15, #12 and
the facing dot in #20 are in the ELF's order; the inexact literals 0x3eb33333, 0x3dcccccd,
0x3e99999a, 0x3da3d70a, 0x3c23d70a (#20), 0x3a83126f, 0x3f34fdf4 (#12), 0x3ca3d70a (#32) and
0x30000000 (#21, #26) equal the port's spellings; no argument goes on the stack (the ActivateArg
varargs stay in a1..t2); no startup-computed constants.

Leads for other lists:
- zNode: CNode::SetActive is virtual in the ELF (vtable slot 0x34, CLight overrides it) but not in
  the port's znode.h, so a port call through a CNode* never reaches CLight::SetActive (#20 calls it
  on the moving node through the vtable; #22's port calls are on CLight* and so are right).
- zanim_menu.cpp UIActivateButton (0x1d3b70, not in this list) has the same m_arg_list NULL test
  as #34.
- zanim.h: _zanim_sound::stop_on_exit is bool in the port, sshort in DWARF (the ELF stores a
  halfword); harmless while GetSoundRef memsets the entry.

What the packets lacked: the inlined helpers' bodies listed under Method (read from the source),
and the bodies of CreateRootNode 0x1caff0, GetNodeRef 0x1cb430 and LoadZAR(CZAnimZAR*) 0x1c0340
(disassembled from the cached full listing); the command layouts (_zanim_cmd_motion, _particle,
_light, _camera, _fire_weapon, _call_anim, _motion_from_to, CZAnimFromToAcc, _zanim_node_ref,
_zanim_sound) and the DWARF layouts of Particle::Source / Props, zdb::CLight / CLightMap / CCamera,
CZProjectile, _zvid_public and sceNetcnfifData (port/compat); the vtables of CNode, CLight,
CLightMap, CModel and CSnd to name the indirect calls; three unannotated strings (0x44c518 "",
0x44c520 "PREVIOUS_SCREEN" in #34). Packet labels: every command offset is labelled
"timeless:1@17" (the header's bit, not the member), and #7 labels +0x16 with the wrong half of the
word (it is m_cleanup_seq_offset). Scan noise met besides the known kinds: GCC's CCamera / CNode
layout (vtable pointer first) shows as different offsets in #24 / #25; strings the linker merged
as suffixes ("NAME", "HEALTH", "ON") and a string built with a lui in an earlier delay slot
("SHIELD") show as missing.

Runs: the default build links (`default.sh audit-anim-c-default`, 0 undefined). One smoke run: `gate.ps1 -Only roundtrip` on HEAD aaf00559 + this
list's files passed (menus -> m8 -> menus four times, in-use memory flat). No targeted trace: the
B fix needs two contacts on different materials in one frame, which no m8 run can be steered to.
