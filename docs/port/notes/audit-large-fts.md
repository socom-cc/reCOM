# Audit of list large-fts (2026-11-16, socom-port-audit-fts)

26 zFTS functions (33,392 bytes) in `gamez/zFTS/fts_action.cpp`, `fts_controller.cpp`,
`fts_mission.cpp`, `fts_net_game.cpp`, `fts_net_persona.cpp`, `fts_net_seal.cpp`,
`fts_network_dme.cpp`, `fts_player.cpp` and `fts_remote.cpp`. HEAD 03604c19. Judged in the scan's
rank order, each over its whole address range.

Method: each function read instruction by instruction against the port's body, with the port
helpers the ELF inlines (GetCellPos, NewConfig, ftsNetworkGameInit, the inline CValve::Set,
the inline _zrdr Get / GetInt, CMatrix::Transform, GetBBox) and the DWARF layouts of the
structures they touch (CZNetGame, CZSealBody, CZNetVoice, CEntityList, CWorld). The network
files (`fts_net_*.cpp`, `fts_network_dme.cpp`, `fts_remote.cpp`) cannot run on this disc: their
rows are read-only evidence, without a trace.

Defect rate 5 / 26 (B 1 / 26).

Fixes:
- B, #6 CZNetGame::Initialize: rewritten from 0x1f4090. The start flag is NET_READY_WAITING
  (+0xda = 1); LateJoiner(false) instead of clearing m_was_late_joiner; the chat-list reader
  is push(NULL)/pop'ed into an empty array (0x1f4174); the mp_minor_game_state (0x1f41ec),
  mp_x_sec_clock and mp_prog_timer1 (30) valves are made, so MyMinorGameState (UISetMenuState,
  also offline) no longer writes through a NULL valve; the inline Set(0) after most valves and
  Set(1) for mp_bomb; "mp_round_count" for "round_count" (0x1f44d4).
- C, #20 IncrementalUpdateRemoteSeal: the bit-30 death test as the ELF's `c.le.s health, 0;
  bc1t` (0x205348), was `health > 0` (NaN only).
- C, #2 CCtrlrConfigs::Init: the config loop compare is signed (0x20a084 slt), was unsigned.
- C, #8 aiMapPlaceItem: the eight bbox corners in the ELF's order (0x1f5830-0x1f5958) and the
  lowest kept with ai::_min<f>'s `corner <= lowest` (0x1fac10), was binary order and std::min
  (NaN and signed-zero ties only).
- C, #22 DMERegister: no NetRegisterMessageStart before the weapon pickup packet's fields
  (0x201c4c follows the chat registration 0x201c38), as the ELF (quirk noted in the code).

Kept deviations (reasons in the code): #7 ftsFixupAiMap: the pickup position zeroed where the
ELF leaves it unset off the map, a NULL position for the fiftycal_box CreateInstance (the ELF
passes unset stack, which aiMapPlaceItem overwrites), and the NULL test of the first two ammo
entry fields (the ELF reads the type byte at address 0 for a short entry; reason added); #14
PreOpen: the empty-postfix default tests the pointer, the ELF tests zrdr_findSTRING's answer
(0x1f8a6c; only a value 0 differs, where the ELF would strncpy from address 0; reason added).
Comment corrected: #13 Open's "guess" about the first word of CEntity::m_list is the MSL list's
size (CreateEntity 0x1ef670 sets m_index from it).

Leads for other lists: none outside this list's files. CWorld's clutter manager is reached
through the port's `m_grid` pointer where the DWARF has the grid embedded (world +0x698); the
same layout choice appears wherever a list touches the world's grid.

What the packets lacked: the bodies of the inlined helpers named above (fetched from the
source), the text of very short strings ("m" 0x44dd78, "0" 0x44dd20), the bodies of out-of-line
helpers whose compare form matters (ai::_min<f> 0x1fac10, read with dis.sh), enum values
(MP_NET_READY, SEAL_CONTROL_TYPE, MP_GAME_TYPE, E3 team, PU_TYPE, ACTION_TYPE), the members of
DWARF types the packets did not name (CZNetGame +0xd9..+0xe4, CZSealBody damage fields,
CZNetVoice buffers, CWorld +0x698), and the nops in two branch sequences (0x1f5574 checked
with dis.sh; the missing NetRegisterMessageStart in #22 checked the same way).

Runs: the default build links (`default.sh audit-fts-default`); smoke: `gate.ps1 -Only
roundtrip` on this tree (menus, m8, menus; Init, PreOpen, Open with the pickups, Close):
PASS, 4 returns, in use 18,657,132 B flat; the ammo-box pickups placed by aiMapPlaceItem logged.
