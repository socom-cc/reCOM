# Audit of list medium-ui-a (2026-11-19, socom-port-audit-mui-a)

The 75 medium functions of the first half of `gamez/zUI/zui_2d.cpp` (27,580 bytes): the 2D
buttons, check box, slider, radio strip, cycle button, list box rows, map control, texts,
teletype, counter and clock. HEAD 0e13d498. Judged in the scan's rank order, each over its whole
address range, on the ELF offsets the zui.h comments give (the scan's offset lists compare the
port's own layouts, which differ where UIVarMixin or the vtable pointer sits elsewhere).

## Fixes

- C `CTeleType::GetZAnimCmdType` 0x390330: an unknown name gets `GetUICommandType(NULL)` (the
  delay slot's zero before 0x3903e4), as `CRenderableString::GetZAnimCmdType` 0x388cf0; the port
  passed the name.
- C `C2DCounter::GetZAnimCmdType` 0x393160: the same (0x39323c).
- C `CUIMapCtrl::ParseZAnimCmd` 0x385eb0: the port's NULL test of the PAN DIRECTION string
  removed; the ELF calls strcmp on it untested (0x385f74), kept as an ELF quirk (comment).
- No verdict change, code written as the ELF: the string rows' fade minimum in both `DrawPrep`s
  (0x392180, 0x391de0) now has the row test the ELF has (same value: the glow branch is only
  reached on the selected row); their comments said the ELF had none. The comment of
  `C2DCounter::TickZAnimCmd` said Start returns 2; it returns 1.

## Kept deviations

None new. Noted only: the `CUIMapCtrl` ctor also zeroes the window (said in the code; LoadSpec
sets it next).

## Leads for other lists

- `PrepListItem` loads an IMAGE cell with (LENGTH, WIDTH) while the cell keeps width = WIDTH,
  height = LENGTH (ELF, kept): the image-row Draw / SetPos code elsewhere should read the cell's
  own fields, not assume the bitmap's.
- No other `GetZAnimCmdType` in `src/` passes the name to `GetUICommandType`.

## What the packets lacked

- Enumerator values the bodies name through other types: `ActionItem::ACTION_TYPE_EVENT` /
  `ONACTIVATE` (row 42), `ZRDR_INTEGER` / `ZRDR_REAL` (rows 33, 2); read from the headers.
- The receiver's ELF offsets for the undocumented zUI classes (zui.h comments) and the spec
  layouts (`CTextSpec`, `CTtySpec`, `CUIVariableSpec`).
- A base-class body reached by a qualified call (`C2DButton::TickZAnimCmd`, row 22) and a
  sibling the fallback should agree with (`CRenderableString::GetZAnimCmdType` 0x388cf0, fetched
  with `dx.ps1`); the out-of-file `C2D::C2D` (row 13).
- Data words of a function static (`c_arrAnchors$3348`, `od.sh`).
- Exact addresses: the compacted listing drops instructions, so counting lines gave 0x385f38 for
  the jalr at 0x385f48 (`dx.ps1` used for the cited addresses).

## Runs

- Default build (`default.sh audit-mui-a-def`, HEAD 0e13d498 + this file's two changes): links
  (library and link exit 0).
- Smoke boot of that build (`run.ps1 -Build audit-mui-a-def -Name mui-smoke -Seconds 60`): the
  intro movies, then `dlgMenu.rdr` (main menu) at 24 s and the attract `dlgHype.rdr` at 35 s; no
  STOP or exception. No targeted trace: no A or B fix.
