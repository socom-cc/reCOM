The 32 large functions of `Apps/FTS/game` (database, orders, thezoom), `Apps/FTS` (getopt,
options) and `Apps/FTS/state`; 48,924 bytes. HEAD d816381d. Judged in the scan's rank order, each
over its whole address range.

## Fixes

- B `CMenuState::Init` 0x3793e0: with m_skip in a network game DMEinit, DMEConnectToGameServer,
  DMEJoinGameServer and ftsNetworkGameInit follow CreateNetGame (0x379428-0x379440).
- B `LoadWorld` 0x172b60: the node universe is emptied (size_ 0) before the load and on a failed
  load (0x172bc0, 0x172bf8); ReleaseDataBuffer also for a library without models (0x173338); the
  result is the last models.zar Open (0x173480); the far clip test as !(far <= mid) (0x173458).
- B `OrdersMenu::ScrollForward` 0x175420: the step to the next column tests that column's size,
  m_size[col + 1] (0x1759ec); a team without allowed orders no longer opens an empty column.
- C `OrdersMenu::SetupTuples` 0x179da0: the LASE crosshair tuple's object text is "" (0x17a338).
- C `C2DOrderItem::Tick` 0x17bbf0 and `HandleMoving` 0x17bfb0: three compares in the ELF's NaN
  form (0x17be3c, 0x17be88, 0x17c23c).
- C `CMPExitState::Init` 0x3dcee0 and `SetMpStatUiVars` 0x3dd820: port seal NULL guards the ELF
  lacks removed (0x3dd1f8, 0x3dd8f0; ELF quirk commented).

## Kept deviations (reasons in the code)

- `OrdersMenu::SetupContextDisplay` 0x178eb0: an unfilled context entry shows "" (ELF: strncpy
  from address 0).
- `OrdersMenu::HandlePad` 0x175ff0: UP in the first column wraps before the has_command test (ELF
  tests team_table[-1]; that byte, 0x4386e8, is 0 in the ELF's data).
- `CE3Config::Parse` 0x37e080: the entry's first element is NULL-tested before its type is read.
- `CMenuState::RunEventAnim` 0x3788c0: returns 1 for a run event (CGameMenu::RunEventAnim is void
  in the shared zgame.h; only the online UILobbyEventHandler reads it).

## Leads for other lists

- `zdb::CNode::SetActive` is virtual in the ELF (vtable +0x34, called through it by
  CMPExitState::Init's reset loop after 0x3dd208 and CCoreState::Tick's first-person hide around
  0x17cfb0); the port's is not, so a CLight
  reached through a CNode * misses its override (world list, znode.h).
- `CGameMenu::RunEventAnim` returns whether an anim ran in the ELF; the port's is void (zUI,
  zgame.h).
- ztwod.h:202 declares a stale `bool C2DBitmap::GetTrans() const` beside `float GetTrans()`.
- st_mpexit.cpp's medium functions (SetStatLbUiVar, SetFinalTeamTotalsUiVar, TickMpStats) keep
  port seal NULL guards the ELF lacks (medium band).
- The port's `_zsys_public` and `CMission` layouts differ from the ELF's (cdSounds +0x22 vs +0x1e,
  m_ordersRdr +0x574 vs +0x594, m_winlosstimer +0x6c vs +0x68); consistent within the port, scan
  noise here.

- Enum values (FT_COMMAND, ZOOMSTATE, _RenderPhase, MP_NET_READY, MP_GAME_TYPE, KEY_STATE,

- #10 labels `lbu 0(a0)` on reader entries as OrdersMenu::m_no_menu; #17 and #26 lose the labels
  of branch targets that follow an unconditional branch (L17c21c, L37f3dc).
