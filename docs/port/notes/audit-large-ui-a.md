The 28 large functions of the first half of zUI: `gamez/zUI/zui.cpp` (8), `zui_2d.cpp` (19),
`zui_tuner.cpp` (1); 37,336 bytes. HEAD 75e81077. Judged in the scan's rank order, each over its
whole address range.

## Fixes

- B `CGameMenu::Clear` 0x3835a0: texture buffer 0's texture and palette lists and the font's
  character vector now give their storage back (clear + swap with an empty vector,
  0x3836f0..0x383738, 0x383778..0x3837a0); the port only cleared them.
- B `CCycleButton::HandlePad` 0x38a090: the walk to the new option keeps the first walk's counter
  (0x38a220 / 0x38a34c), so RIGHT runs the second option's ONACTIVATE anim and LEFT the first's
  (ELF quirk now kept and commented).
- C `CPopUpDialog::ParseZAnimCmd` 0x387c00: a missing YES / NO button also zeroes the dialog's
  m_yesTextOffset.y / m_noTextOffset.y (0x3885a8, 0x388ca4; ELF quirk, commented).
- C `ParseButtonAnim` 0x380f50: the EVENT part's allocator lines are 1593 / 1595 (0x381480).
- C port NULL guards the ELF lacks, removed: the pop-up caption before its strcmp
  (`CPopUpDialog::TickZAnimCmd` 0x387088), the pop-up before its Tick (`CGameMenu::Tick`
  0x380a00), the teletype sound in the tail (`CTeleType::Tick` 0x38ff50; its reason "the port
  has no sounds" was stale), the variable before the PERMANENT store (`InitSystemTuners`
  0x3a2290).

## Kept deviations (reasons in the code)

- `CUIListBox::UpdateUIVar` 0x38d8a0: the spec FONT is not deleted there (the ELF deletes it while
  m_font keeps pointing at it); and the two rows below.
- `CUIListBox::UpdateUIVar` (new at 0x38dad0) and `CListItemArrayTypeImpl` ctor 0x3929b0 (new at
  0x392b70): the string row's m_colorSet is cleared by the port's ctor; the ELF's inline ctor
  leaves the heap's byte (comments added).
- `CGameMenu::Tick` 0x380700: a command node without a 2D visual skips SetCanHandleInput; the ELF
  calls through a register left from before (0x3809a0).

## Leads for other lists

- The string row's uninitialised m_colorSet (inline `CListItemStringTypeImpl` ctors without the
  +0xb0 store) may appear in other row makers (`CListItemTimedTextTypeImpl`, `ItemImpl` callers).
- `docs/port/notes/mod-zui.md` part 1 lists the `InitSystemTuners` NULL test as a port deviation:
  it is removed here.

## What the packets lacked

Packet 11 showed only the two helpers above the function (its body was read from the source).
Not in the packets and fetched: same-file helper bodies (`ItemImpl`, `MapCovers`,
`RadioShowSelection`, `PopUpSetButton`, `IsStickNearCenter`, `UiGetDirStickMoved`, `GetStickDir`,
`CPlainBmp::Draw`, `CRenderableString` ctor, `~ListItem`, `ActionItem::operator=`, `Add2dNode`,
`MakeTuner`); vtable slots (`vt.py` on C2DButton, CNode, CGameMenu, CWrappedText,
CRenderableString, CListItemStringTypeImpl); enum values (PAD_BUTTON, KEY_STATE, VALVE_TYPE,
UIVAR_LONGEVITY, ActionItem::EVENT); the ELF offsets of the undocumented zUI classes (zui.h
comments; the scan's offset lists compare the port's own layout, which differs); the content of
`achFallback$3573`; exact instruction addresses (`dis.sh`; the compacted listing has labels only);
the callees deciding the guards (`CMenuStack::GetPopUp`, `CSnd::GetSoundByName`,
`CUIVarManager::Add`).
