# Audit of list large-anim-b (2026-11-16, socom-port-audit-anim-b)

22 zAnim functions (47,152 bytes) in `gamez/zAnim/anim_main.cpp`, `zanim_cmd_parse.cpp`,
`zanim_sequence.cpp` and `zanim_set.cpp`. HEAD cb01af90. Judged in the scan's rank order, each
over its whole address range.

Method: each function was read instruction by instruction against the port's body, including
the port's helper functions that the ELF inlines (zAnimDebugAddString, ParticleVelocity,
ParticleRotateRate, ParticleTableCount, zAnimSIScriptAddObject, CZAnimNameTable::AddName,
zAnimGetDirectionFromAzimuthZenith, zAnimCmdAddData). InitCommands (48 AddCmd calls) was read
call by call by hand; no script was needed.

Defect rate 0 / 22. No fixes.

Code change: one comment only, in zAnimLoadParticleSource (MODEL: the port's NULL model name
where the ELF leaves the stack slot unset when MODEL has no NAME).

Kept deviations: none new. Already recorded in the code and confirmed: the zeroed stack slots
(OBJECT_MOTION base / min / spin / roll, load_si_script's vectors and last values, LIGHT's
blend selectors, PARTICLE_SOURCE's streak pair and rotate-rate buffer), the CFileIO
OBJECT_MOTION_SI_SCRIPT builds and destroys unused, load_si_script returning void.

ELF quirks kept (all already commented in the code): OBJECT_MOTION drops the whole command on an
unknown FORWARD_ROTATION kind and DO_INTERSECTIONS implies DO_ALTITUDES; FIRE_WEAPON reads
RELATIVE_NODE and AZ from the command; PARTICLE_SOURCE appends the ROTATED rotate rate twice and a
missing single ACCELERATION zeroes the velocity pair; LIGHT sets is_local_light without a node-ref
test; SI_SCRIPT's NAMES path looks SCRIPT_OBJECT_NAME up on the list; DESTRUCTION_SOURCE keeps the
record on no NODE, repeats the last pair for a missing velocity tag and reads OPACITY from the
COLOR tag; ANIM_LOD tests ">=" twice; InitCommands registers three commands twice; ClipToBox tests
y_at_xmax (just y) in the below-ymin / before-xmin case.

Float checks: no three-term sums in these bodies; inexact literals 0x3a83126f, 0x3c8efa35,
0x3c360b61, 0x3e99999a, 0x3727c5ac, 0x3c23d70a, 0x3d088889 all match the port's spellings; no
stack-passed arguments beyond the a0-t3 / f12-f15 registers (CZAnimSet::SIScript, _store_frame_data
compared register by register); no startup-computed constants.

Leads for other lists: none.

What the packets lacked: #4 showed only the helper zAnimDebugAddString under the stub marker, not
the zAnimLoadDebug body after it (read from zanim_cmd_parse.cpp 3682-3773); #18's three helpers,
#5's zAnimSIScriptAddObject, #1's CZAnimNameTable::AddName and #3's
zAnimGetDirectionFromAzimuthZenith were read from the source; the struct layouts
(_zanim_cmd_motion, _camera, _debug, _particle, _fire_weapon, _lod_test, _zanim_node_ref,
_zanim_motion_material) and _zrdr::Get / GetReal from the headers; two unannotated strings
(0x44a030 "<", 0x44a040 ">") with sym.py; one dis.sh range in #22 to see a branch target the
compacted listing hides. #14 and #21 name members wrongly (#14 reads a static's arguments as
this; #21 gives one bit name for a whole byte).

Runs: none (one comment changed). The default build links (`default.sh audit-anim-b-default`).
