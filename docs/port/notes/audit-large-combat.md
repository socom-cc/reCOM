# Audit of list large-combat (2026-11-16, socom-port-audit-combat)

40 functions (47,764 bytes) in `gamez/zCharacter/char_type.cpp`, `gamez/zNetwork/zNetCnf.cpp`,
`zNetDme.cpp`, `zNetMedius.cpp`, `zNetVoice.cpp`, `gamez/zVehicle/veh_turret.cpp`,
`vehicle_main.cpp` and `gamez/zWeapon/zwep_projectile.cpp`, `zwep_projectilelist.cpp`,
`zwep_weapon.cpp`, `zwep_weaponlist.cpp`. HEAD c7288dac. Judged in the scan's rank order, each
over its whole address range. The network files (`zNet*.cpp`) cannot run on this disc: their
rows are read-only evidence, without a trace.

Method: each function read instruction by instruction against the port's body, with the port
helpers the ELF inlines (turret_sees, turret_draw / turret_rearm, LobbySetStateValve,
LobbyReleaseList, LobbyAppendMOTD, LobbyAddLadderRow / LobbyRequestTop10, LobbyPrepareRequest,
VoiceStartWorker, GetDecalNode, PreFireProjectile / FireValidityCheck, SetProjectileState, the
CCnfStateMachine Tick, _zrdr::Get / GetReal) and the out-of-line callees whose compare form
matters (ai::_max<f> 0x26c8a0, _saturate<f> 0x1a8dd0, Rfloat::operator float 0x25aba0). The scan
was made on an older fingerprint commit (f7c2be1f): many of its differences (ZWepReader::Read's
strings, CTurret's calls, the lobby callbacks' stores) are the provisional bodies since replaced.

Fixes:
- C, #24 CTurret::Init: the three ai::_max<f> as `a < b ? b : a` (0x26c8a0) and the field-of-view
  clamp as _saturate<f>'s `!(v <= max)` then `v < min` (0x1a8dd0); were `a > b` and zmath's
  saturate (NaN only).
- C, #9 CZOnlineLobby::JoinGame: the five inline CValve::Set have no NULL test (0x325898..
  0x325a14); new unguarded LobbySetValve (the Tick one, 0x327d0c, does test: LobbySetStateValve
  stays).
- C, #16 LobbyReadyToConnectStateHandler: the closing mp_persistent Set(1) unguarded (0x32d27c).
- C, #28 CFlyoutMachine::AcquireFlyout: the return on `c.lt len, 70` (0x316a34), was
  `!(70 <= len)` (NaN only).
- C, #33 CZProjectile::HandleIntersections: the nearest-hit test skips on `c.le sq, from` and keeps
  on `c.lt sq, range` (0x3192cc, 0x3192f8), was `from < sq` and `!(range <= sq)` (NaN only).
- C, #31 CZProjectile::HandleImpact: the AI event on `!(radius <= 1)` (0x31839c) and the result
  `!(dist <= range^2)` (0x318594), were `radius > 1` and `range^2 < dist` (NaN only).

Comments corrected: #4 the aware_decay word (0xbd99999a), #3 the LOD names (m_name the file as
given, m_file cut at ".xsi"), #37 the shotgun spread takes an indirect DI; reason added: #17
cbRoomList's snprintf.

Kept deviations (reasons in the code): #38 ZWepReader::Read zeroes LegAmmoLen's slot (unset in the
ELF); #13 CZOnlineLobby::Open strncpy's the two 8-byte literals where the ELF memcpys 32 bytes;
#32 HandleBounce guards the under-water read of a NULL material; #17 cbRoomList's snprintf; #1
InitMultiplayerMessages' NULL / "" for missing or non-string elements (the ELF reads address 0 /
passes NULL to "%s"); #7 zNetLoadIRX's "" / 0 for an unknown connection type (the ELF passes unset
registers); #16 also keeps the GameName / GameStats strncpy where the ELF memcpys past the strings.

Leads for other lists:
- `LobbyShowRoomChat` in zNetMedius.cpp calls itself (infinite recursion, since ae072df3); its
  callers are cbFilterChat 0x324de0 and cbLobbyServerConnect 0x32d630 (not on this list; online
  only, a crash there). Needs the inline body from 0x324de0.
- `saturate<T>` in zmath.h tests `value > max` first; the ELF's _saturate<f> (0x1a8dd0) is
  `!(v <= max)`: a NaN-only difference for every port caller that stands for _saturate<f>.
- `net_init_thread_stack` (#13 Open uses it) is the known unaligned port array, left for the
  user's decision.

What the packets lacked: the bodies of the inlined port helpers named above (read from the
source), the out-of-line callees whose compare form matters (ai::_max<f>, _saturate<f>,

0x31d6a0..0x31d6d8, the compare addresses: checked with dis.sh), the 20 bytes of "-verbose" at
