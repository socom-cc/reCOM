## Fixes

- B, #18 CGrid::gridGetNextIndex, the polygon walk (three or more boundary points): the step
  test is `(m_RowCellIn == 0 || m_CurCellOut == 0) && m_zz < m_izb - 1` (0x215b64-0x215b8c; the
  port's `a || b && c` stepped past the last row of a column with no cell in), a new column
  started below the next row goes one row back (0x215bfc, was forward), the walk's end stores
  m_CurCellOut 1 (0x215c34, was 0). Masked: every caller of GetNextAtom / gridGetNextIndex passes
  one or two points (the ordered render walk does not use it), so the branch is not reached here.

Kept deviation (reason in the code): #42 CalcWorldToUV zeroes the axis vector whose other
components the ELF leaves as uninitialised stack.

ELF quirks kept (already commented in the code): #31 proj rotated and dropped; #37 the detail
range test reads record 0 each pass; #46 the do-while qword copies; #7 the out-of-range return
without the local-lights restore; #24 / #25 a non-cell slot ends the walk; #29 the dead walk-in
loop.

Float checks: the three-term sums ((x x + y y) + z z) in #7, #12, #13; the two-term edge dot
products and lengths in #19, #20, #21; the VU0 transforms (x r0 + y r1 + z r2 (+ r3 w)) in #31,
#35, #36; the products' operand order in #39, #44, #22, #13, #54, #27; the compare forms (NaN
cases) one by one in #3, #7, #22, #23, #44; no float-to-unsigned conversion in this list (every
conversion is fptosi, matched by the port's (s32)); literals 0x3a83126f, 0x3c010204, 0x38d1b717,
0x3b808081, 0x48f42400 / 0xc8f42400, 0x7f7fffff, 0x4000000000000000 checked against the port.

Leads for other lists: none new. The `_zvid_public` layout lead (audit-large-world) shows up in
#54 (the frame byte at +0x10 in the ELF, the port's s64 at +8): harmless, read by name.

What the packets lacked: nothing needed beyond the headers for bit positions (tag_VIS_PARAMS,
tag_NODE_PARAMS, CClutter) and the VU1 command enum values (port-only enum in zvis.h, not given
as values); the CLightMap member offsets (DWARF) were inferred from the loads, as the packet named
the light map's register type only as unknown; the out-of-line ~CClutterAnim (#4) and
CMesh::DereferenceDecals (#51) bodies, which the ELF inlines, were read from the source.

a5b1639b + these files. One fake-pad m8 run (`common/pad_start.txt`, 170 s,
`audit-mgridvis-fake`): no STOP, the mission ran from the cameras' end (~80 s) to frame 3427 at
